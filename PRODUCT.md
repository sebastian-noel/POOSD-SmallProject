# Product

## Register

product

## Users

People managing a small, private address book on laptops and phones. The project
is a UCF contact-manager application, also demonstrated in a classroom. Users
need to sign in, find a person, and maintain contact information without learning
a complex CRM.

## Product Purpose

Keep each user's contacts private and easy to find. Registration, login,
server-side partial search, and contact creation/editing/deletion are the core
workflows. Retain the existing PHP/MySQL API and plain HTML/CSS/JavaScript client.

## Brand Personality

Calm, minimal, focused. This direction was selected by the user for the redesign. Retain the existing Contact Manager product name.
Use concise, friendly language and clear action labels.

## Anti-references

Avoid generic sales dashboards, invented metrics, decorative card grids, fake
navigation, nonfunctional links, and motion that delays a task. Do not style the
address book as an enterprise CRM or a marketing landing page.

## Design Principles

- Make finding and maintaining a contact the main event.
- Preserve user input when requests fail and make recovery obvious.
- Keep contact ownership and session handling in the existing backend.
- Use a consistent form and action vocabulary across all three screens.
- Give feedback through both readable text and visual state.

## Accessibility & Inclusion

The user explicitly requested better accessibility. Target WCAG 2.2 AA design
practices: clear labels, readable contrast, visible keyboard focus, reflow on
small screens, status announcements, and reduced-motion support. Compliance
requires testing; this document is an implementation target, not certification.
